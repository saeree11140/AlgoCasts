วิธีคิดก่อนเขียน SQL และข้อควรจำเรื่องฐานข้อมูล
  1. ดูว่าต้องแสดงข้อมูลอะไร และหนึ่งแถวในคำตอบหมายถึงอะไร เช่น หนึ่งคนหรือหนึ่งวัน
  2. ดูว่าต้องใช้ตารางใด และเชื่อมกันด้วยรหัสไหน (key) ถ้ารหัสหนึ่งมีหลายแถวในทั้งสองตาราง ต้องระวังยอดถูกนับซ้ำหลังเชื่อม (JOIN)
  3. จดเงื่อนไขที่พลาดง่าย: ค่าขอบเขต ค่าที่ไม่มี (NULL) ข้อมูลซ้ำ และวิธีเรียงเมื่อค่าเท่ากัน (tie-break)
  4. ถ้าต้องรวมหลายขั้น ให้คิดทีละขั้นว่าหนึ่งแถวต้องแทนอะไร เช่น เลือกคะแนนดีที่สุดต่อคนต่อข้อก่อน แล้วค่อยรวมคะแนนต่อคน (aggregate)
  5. ลองคำนวณผลจากตัวอย่างด้วยมือ แล้วเช็กกรณีไม่มีข้อมูล มีแถวเดียว ข้อมูลซ้ำ และค่าเท่ากัน (edge cases)
  6. ก่อนส่ง เช็กว่าชื่อและจำนวนคอลัมน์ตรงโจทย์ รวมถึงลำดับแถวด้วย (ORDER BY)

เฉลยใช้ PostgreSQL 16 ฐานข้อมูลแต่ละชนิดเขียนคำสั่งบางอย่างต่างกัน (SQL dialect) ถ้าใช้ MySQL หรือ SQL Server ต้องปรับคำสั่งก่อนรัน

จุดที่ควรเช็กเมื่อเปลี่ยนฐานข้อมูล: การเลือกจำนวนแถว (LIMIT / TOP), การคำนวณวันที่, กฎเรียงตัวอักษร (COLLATE) และการสร้างรายการวัน (generate_series) เฉลยยังไม่ได้ตรวจบน MySQL หรือ SQL Server

Q01 · Basic · 8 MIN

พนักงานที่ผ่านเกณฑ์

แสดงพนักงานแผนก Platform ซึ่งยัง active และมี salary มากกว่า 50000 โดยคืนเฉพาะ employee_id กับ name

ข้อกำหนด / Output

  • salary = 50000 ไม่ผ่าน; salary เป็น NULL ไม่ผ่าน
  • เรียง employee_id ASC; คืนศูนย์แถวถ้าไม่มีคนผ่าน
  • name ใช้ ASCII A–Z/a–z ไม่มีช่องว่าง; ไม่ต้องจัดการ case ของชื่อ

Columns: employee_id, name

ข้อตกลงของข้อมูล

แต่ละตารางมีได้ 0–100000 แถว ข้อมูลอ้างอิงระหว่างตารางถูกต้อง (foreign key) รหัสเป็นจำนวนเต็มบวก (integer) และชื่อมีค่าเสมอ (text, NOT NULL) เว้นแต่ข้อกำหนดของข้อนั้นระบุเพิ่ม ในตารางตัวอย่าง NULL หมายถึงไม่มีค่า และ “ไม่มีแถว” หมายถึงไม่พบผลลัพธ์

Schema

CREATE TABLE employees (
  employee_id integer PRIMARY KEY,
  name text NOT NULL,
  department text NOT NULL,
  active boolean NOT NULL,
  salary integer CHECK (salary >= 0)
);

คน 1 และ 6 ผ่านครบสามเงื่อนไข คน 2 อยู่ตรงขอบจึงไม่ผ่าน คน 5 ไม่มี salary

เปิดแนวคิดทีละขั้น
  1. ดูว่าพนักงานแต่ละคนอยู่แผนก Platform, ยังทำงาน และได้เงินเดือนมากกว่า 50000 ครบหรือไม่
  2. เก็บเฉพาะคนที่ผ่านทุกเงื่อนไข (WHERE และ AND) แล้วแสดงรหัสกับชื่อ (SELECT)
  3. เรียงรหัสพนักงานจากน้อยไปมาก (ORDER BY employee_id) แม้ข้อมูลตัวอย่างจะเรียงมาแล้ว
เปิดเฉลย · จุดพลาด · เช็กก่อนส่ง

Reference SQL · PostgreSQL 16

SELECT employee_id, name
FROM employees
WHERE department = 'Platform'
  AND active = TRUE
  AND salary > 50000
ORDER BY employee_id;

จุดพลาด

  • ใช้ >= จะรับค่าขอบ 50000 ผิด
  • ใช้ OR รับคนต่างแผนกหรือ inactive
  • salary NULL เปรียบเทียบแล้วเป็น UNKNOWN จึงไม่ผ่าน WHERE

เช็กก่อนส่ง

  • คืนเฉพาะสอง column
  • ทดสอบค่าขอบ, NULL, inactive และตารางว่าง

สแกน employees; index ตามเงื่อนไขช่วยบาง workload แต่ต้องดู selectivity และ EXPLAIN จริง

Q02 · Basic · 10 MIN

ชื่อ depot สั้นสุดและยาวสุด

คืนชื่อ depot สั้นที่สุดหนึ่งชื่อและยาวที่สุดหนึ่งชื่อ พร้อมจำนวนตัวอักษร ใส่ kind เป็น shortest หรือ longest

ข้อกำหนด / Output

  • ชื่อเป็น ASCII A–Z ตัวพิมพ์ใหญ่ 1–30 ตัว ไม่มีช่องว่าง; ชื่อซ้ำได้
  • ถ้าความยาวเท่ากันเลือกชื่อเรียงอักษรก่อน ใช้ collation "C"
  • คืน shortest ก่อน longest; ถ้าทุกชื่อเหมือนกันยังคืนสองแถว; ตารางว่างคืนศูนย์แถว

Columns: kind, name, name_length

ข้อตกลงของข้อมูล

แต่ละตารางมีได้ 0–100000 แถว ข้อมูลอ้างอิงระหว่างตารางถูกต้อง (foreign key) รหัสเป็นจำนวนเต็มบวก (integer) และชื่อมีค่าเสมอ (text, NOT NULL) เว้นแต่ข้อกำหนดของข้อนั้นระบุเพิ่ม ในตารางตัวอย่าง NULL หมายถึงไม่มีค่า และ “ไม่มีแถว” หมายถึงไม่พบผลลัพธ์

Schema

CREATE TABLE depots (
  depot_id integer PRIMARY KEY,
  name text NOT NULL CHECK (name ~ '^[A-Z]{1,30}$')
);

Sample Input

Sample Output

AX กับ BO ยาว 2 จึงเลือก AX; DELTA กับ GAMMA ยาว 5 จึงเลือก DELTA

เปิดแนวคิดทีละขั้น
  1. นับตัวอักษรของแต่ละชื่อ (CHAR_LENGTH) แล้วหาชื่อสั้นที่สุดกับยาวที่สุดแยกกัน
  2. ถ้าหลายชื่อยาวเท่ากัน ให้เลือกชื่อที่มาก่อนตามลำดับอักษร ใช้กฎเรียงอักษรเดียวกันทุกครั้ง (COLLATE "C")
  3. นำสองคำตอบมาต่อกันโดยเก็บไว้ทั้งคู่ (UNION ALL) ถ้าตารางมีชื่อเดียว ชื่อนั้นจะเป็นทั้งคำตอบสั้นสุดและยาวสุด
  4. ใส่เลขลำดับภายใน 1 และ 2 เพื่อเรียง shortest ก่อน longest แต่ไม่แสดงเลขนี้ในคำตอบ
เปิดเฉลย · จุดพลาด · เช็กก่อนส่ง

Reference SQL · PostgreSQL 16

WITH shortest AS (
  SELECT name, CHAR_LENGTH(name) AS name_length
  FROM depots
  ORDER BY CHAR_LENGTH(name), name COLLATE "C"
  LIMIT 1
), longest AS (
  SELECT name, CHAR_LENGTH(name) AS name_length
  FROM depots
  ORDER BY CHAR_LENGTH(name) DESC, name COLLATE "C"
  LIMIT 1
), picked AS (
  SELECT 1 AS position, 'shortest' AS kind, name, name_length FROM shortest
  UNION ALL
  SELECT 2, 'longest', name, name_length FROM longest
)
SELECT kind, name, name_length FROM picked ORDER BY position;

จุดพลาด

  • MIN(name) วัดลำดับอักษร ไม่ใช่ความยาว
  • เลือก longest แล้ว sort ชื่อ DESC ผิด tie-break
  • อย่าพึ่งลำดับของ UNION ALL โดยไม่มี ORDER BY ภายนอก

เช็กก่อนส่ง

  • ทดสอบชื่อยาวเท่ากันและชื่อซ้ำ
  • ตารางหนึ่งแถวต้องได้สองแถว

สองส่วนใช้ top-N sort; CHAR_LENGTH นับตัวอักษร ต่างจาก OCTET_LENGTH ที่นับ byte

Q03 · Basic · 10 MIN

มูลค่ารายการสูงสุด

คำนวณ gross = quantity × unit_price ของแต่ละ sale แล้วคืน max_gross และจำนวนรายการที่ได้ค่าสูงสุดเป็น sale_count

ข้อกำหนด / Output

  • quantity และ unit_price เป็น integer 0–1000000 ไม่เป็น NULL
  • คืนหนึ่งแถวเสมอ; ตารางว่างคืน max_gross เป็น SQL NULL และ sale_count = 0
  • นับ sale_id แม้หลายรายการมี gross เท่ากัน

Columns: max_gross, sale_count

ข้อตกลงของข้อมูล

แต่ละตารางมีได้ 0–100000 แถว ข้อมูลอ้างอิงระหว่างตารางถูกต้อง (foreign key) รหัสเป็นจำนวนเต็มบวก (integer) และชื่อมีค่าเสมอ (text, NOT NULL) เว้นแต่ข้อกำหนดของข้อนั้นระบุเพิ่ม ในตารางตัวอย่าง NULL หมายถึงไม่มีค่า และ “ไม่มีแถว” หมายถึงไม่พบผลลัพธ์

Schema

CREATE TABLE sales (
  sale_id integer PRIMARY KEY,
  quantity integer NOT NULL CHECK (quantity BETWEEN 0 AND 1000000),
  unit_price integer NOT NULL CHECK (unit_price BETWEEN 0 AND 1000000)
);

Sample Input

31500
40900

Sample Output

sale 1 และ 2 มี gross 600 เท่ากัน จึงคืน 600 | 2

เปิดแนวคิดทีละขั้น
  1. คำนวณมูลค่าของแต่ละรายการ โดยเปลี่ยน quantity เป็นจำนวนเต็มขนาดใหญ่ก่อนคูณ (::bigint) เพื่อรองรับค่าถึงหนึ่งล้านล้าน
  2. หามูลค่าสูงสุดจากค่าที่คำนวณได้ (MAX) ถ้าตารางว่าง ค่านี้จะเป็น NULL
  3. นับรายการที่มีมูลค่าเท่ากับค่าสูงสุด (COUNT) และเก็บแถวสรุปไว้แม้ไม่มีรายการขาย (LEFT JOIN)
  4. นับค่าจากฝั่งรายการขาย (COUNT(a.gross)) เพื่อให้ตารางว่างได้จำนวน 0
เปิดเฉลย · จุดพลาด · เช็กก่อนส่ง

Reference SQL · PostgreSQL 16

WITH amounts AS (
  SELECT quantity::bigint * unit_price AS gross FROM sales
), peak AS (
  SELECT MAX(gross) AS max_gross FROM amounts
)
SELECT p.max_gross, COUNT(a.gross) AS sale_count
FROM peak p LEFT JOIN amounts a ON a.gross = p.max_gross
GROUP BY p.max_gross;

จุดพลาด

  • คูณ integer ก่อน cast เสี่ยง overflow
  • COUNT(*) บน LEFT JOIN จะนับหนึ่งแม้ไม่มี sale
  • COUNT(DISTINCT gross) ได้ 1 แทนจำนวน sale ที่เสมอ

เช็กก่อนส่ง

  • ตรวจตารางว่างและทุกค่าเป็นศูนย์
  • ตรวจ 1000000 × 1000000 = 1000000000000

aggregate และ join แบบเชิงเส้นเป็นแนวทางทั่วไป; planner อาจเลือกต่างกัน

Q04 · Intermediate · 15 MIN

รายงานระดับผู้เรียน

จับคะแนน learner เข้าช่วง grade แล้วคืน learner_id, display_name, grade, marks ถ้า grade ต่ำกว่า 3 ให้ display_name เป็น SQL NULL

ข้อกำหนด / Output

  • grades มี 4 ช่วงตายตัว [0,49]→1, [50,69]→2, [70,84]→3, [85,100]→4 ไม่ทับซ้อนและครอบคลุม marks ทั้งหมด
  • เรียง grade DESC; grade 3–4 เรียง name ASC ด้วย collation "C"; grade 1–2 เรียง marks ASC; สุดท้าย learner_id ASC
  • name เป็น ASCII A–Z/a–z 1–30 ตัว ซ้ำได้; marks integer 0–100

Columns: learner_id, display_name, grade, marks

ข้อตกลงของข้อมูล

แต่ละตารางมีได้ 0–100000 แถว ข้อมูลอ้างอิงระหว่างตารางถูกต้อง (foreign key) รหัสเป็นจำนวนเต็มบวก (integer) และชื่อมีค่าเสมอ (text, NOT NULL) เว้นแต่ข้อกำหนดของข้อนั้นระบุเพิ่ม ในตารางตัวอย่าง NULL หมายถึงไม่มีค่า และ “ไม่มีแถว” หมายถึงไม่พบผลลัพธ์

Schema

CREATE TABLE learners (
  learner_id integer PRIMARY KEY,
  name text NOT NULL,
  marks integer NOT NULL CHECK (marks BETWEEN 0 AND 100)
);
CREATE TABLE grades (
  grade integer PRIMARY KEY,
  min_mark integer NOT NULL,
  max_mark integer NOT NULL
);

เปิดแนวคิดทีละขั้น
  1. นำคะแนนของผู้เรียนไปเทียบช่วงคะแนนในตาราง grades (JOIN และ BETWEEN) คะแนนที่เท่าขอบช่วงยังอยู่ในช่วงนั้น
  2. เลือกแสดงชื่อเฉพาะ grade ตั้งแต่ 3 ขึ้นไป ส่วน grade ต่ำกว่านี้ให้เป็น NULL (CASE)
  3. เรียง grade จากมากไปน้อยก่อน แล้วแยกวิธีเรียงภายในกลุ่ม: grade 3–4 เรียงชื่อ ส่วน grade 1–2 เรียงคะแนน
  4. ถ้ายังเสมอกัน ให้เรียงรหัสผู้เรียนจากน้อยไปมาก เพื่อให้ได้ลำดับแน่นอนทุกครั้ง (ORDER BY learner_id)
เปิดเฉลย · จุดพลาด · เช็กก่อนส่ง

Reference SQL · PostgreSQL 16

SELECT l.learner_id,
       CASE WHEN g.grade >= 3 THEN l.name END AS display_name,
       g.grade, l.marks
FROM learners l
JOIN grades g ON l.marks BETWEEN g.min_mark AND g.max_mark
ORDER BY g.grade DESC,
         CASE WHEN g.grade >= 3 THEN l.name END COLLATE "C" ASC,
         CASE WHEN g.grade < 3 THEN l.marks END ASC,
         l.learner_id;

จุดพลาด

  • join ด้วยเท่ากับ min_mark จะตกคะแนนกลางช่วง
  • ใช้ข้อความ 'NULL' แทน SQL NULL ผิดชนิดข้อมูล

  2. เก็บเฉพาะครั้งที่ได้คะแนนเท่าคะแนนเต็มของข้อนั้น (WHERE score = full_score)
  3. นับจำนวนข้อที่ได้เต็มของแต่ละคน โดยนับข้อเดิมเพียงครั้งเดียว แม้ส่งเต็มหลายครั้ง (COUNT(DISTINCT task_id))
  4. เลือกคนที่ได้เต็มอย่างน้อยสองข้อ (HAVING) แล้วเรียงจำนวนข้อจากมากไปน้อย ถ้าเท่ากันเรียงรหัสคนจากน้อยไปมาก
เปิดเฉลย · จุดพลาด · เช็กก่อนส่ง

Reference SQL · PostgreSQL 16

SELECT p.participant_id, p.name
FROM participants p
JOIN attempts a ON a.participant_id = p.participant_id
JOIN tasks t ON t.task_id = a.task_id
JOIN difficulties d ON d.level = t.level
WHERE a.score = d.full_score
GROUP BY p.participant_id, p.name
HAVING COUNT(DISTINCT a.task_id) >= 2
ORDER BY COUNT(DISTINCT a.task_id) DESC, p.participant_id;

จุดพลาด

  • COUNT(*) นับการส่งซ้ำเป็นหลาย task
  • MAX(score) เทียบกับ 100 ตายตัวทำให้ task 50 คะแนนหาย
  • ใช้ WHERE COUNT(...) ไม่ได้ เพราะ aggregate เกิดหลัง WHERE

เช็กก่อนส่ง

  • คนส่งเต็ม task เดิมหลายครั้งต้องไม่ผ่าน
  • คะแนนเต็มต่างระดับ, tie และไม่มีผู้ผ่าน

ยุบ (participant_id, task_id) ก่อนก็ได้; index บน join keys ช่วยตามแผนจริง

Reference SQL · PostgreSQL 16

WITH best AS (
  SELECT coder_id, problem_id, MAX(score) AS best_score
  FROM scores GROUP BY coder_id, problem_id
), totals AS (
  SELECT coder_id, SUM(best_score) AS total_score
  FROM best GROUP BY coder_id HAVING SUM(best_score) > 0
)
SELECT c.coder_id, c.name, t.total_score
FROM totals t JOIN coders c ON c.coder_id = t.coder_id
ORDER BY t.total_score DESC, c.coder_id;

  • SUM ทุก submission ทำให้คะแนนพอง
  • MAX ต่อ coder ทิ้งคะแนน problem อื่น

  • ชื่อซ้ำ, total 0, tie, coder ไม่มี submission

ช่วงวัน deploy ต่อเนื่อง

รวมวัน deploy ที่ติดกันเป็นช่วงของแต่ละ service คืน service_id, start_date, end_date, day_count โดยนับวันแบบ inclusive

ข้อกำหนด / Output

  • events อาจมีหลาย deploy ใน service และวันเดียวกัน ให้วันนั้นนับครั้งเดียว
  • วันติดกันหมายถึงต่างกันหนึ่ง calendar day; แยก service เสมอ; ช่วงอาจข้ามเดือน/ปี
  • เรียง day_count ASC, start_date ASC, service_id ASC; ไม่มี event คืนศูนย์แถว

Columns: service_id, start_date, end_date, day_count

แต่ละตารางมีได้ 0–100000 แถว ข้อมูลอ้างอิงระหว่างตารางถูกต้อง (foreign key) รหัสเป็นจำนวนเต็มบวก (integer) และชื่อมีค่าเสมอ (text, NOT NULL) เว้นแต่ข้อกำหนดของข้อนั้นระบุเพิ่ม ในตารางตัวอย่าง NULL หมายถึงไม่มีค่า และ “ไม่มีแถว” หมายถึงไม่พบผลลัพธ์

เปิดแนวคิดทีละขั้น
  1. เก็บแต่ละ service ให้เหลือวันละหนึ่งแถวก่อน วันเดียวมีหลาย deploy ให้นับครั้งเดียว (DISTINCT)
  2. เรียงวันของแต่ละ service แล้วใส่เลขลำดับ 1, 2, 3, … แยกกัน (ROW_NUMBER และ PARTITION BY)
  3. นำวันที่ลบเลขลำดับ วันติดกันจะได้ค่าเดียวกัน เช่น 1 ม.ค. ลบ 1 กับ 2 ม.ค. ลบ 2 ได้วันเดียวกัน ใช้ค่านี้เป็นรหัสกลุ่มช่วงวัน (island)
  4. รวมแถวที่เป็น service เดียวกันและอยู่ช่วงเดียวกัน (GROUP BY) แล้วหาวันแรก วันสุดท้าย และจำนวนวัน (MIN, MAX, COUNT)
เปิดเฉลย · จุดพลาด · เช็กก่อนส่ง

Reference SQL · PostgreSQL 16

WITH days AS (
  SELECT DISTINCT service_id, deploy_date FROM deploys
), numbered AS (
  SELECT service_id, deploy_date,
         deploy_date - (ROW_NUMBER() OVER (
           PARTITION BY service_id ORDER BY deploy_date
         ))::integer AS island
  FROM days
)
SELECT service_id, MIN(deploy_date) AS start_date,
       MAX(deploy_date) AS end_date, COUNT(*) AS day_count
FROM numbered GROUP BY service_id, island
ORDER BY day_count, start_date, service_id;

จุดพลาด

  • window ก่อน DISTINCT ทำให้ deploy ซ้ำแยกช่วงผิด
  • ลืม PARTITION BY รวมวันของหลาย service
  • end − start ไม่มี +1 และคืน 0 สำหรับช่วงวันเดียว

เช็กก่อนส่ง

  • วันซ้ำ, ข้ามเดือน/ปี, leap day, หลาย service วันเดียวกัน

สรุป campaign โดยยอดไม่คูณ

รวม views, clicks, orders, revenue ของแต่ละ campaign จาก ads โดย view_stats และ order_stats เก็บยอดจาก batch แยกกัน คืน campaign_id, name และยอดทั้งสี่

ข้อกำหนด / Output

  • หนึ่ง ad สังกัดหนึ่ง campaign; แต่ละ stats table มีหลาย batch ต่อ ad และไม่จำเป็นต้องมีอีกฝั่ง
  • ยอด integer >= 0 ไม่เป็น NULL; revenue เป็นจำนวนเต็มหน่วยบาท; แต่ละ batch นับเพิ่มได้ ไม่ใช่ snapshot
  • รวมค่าหายเป็น 0; ตัด campaign เมื่อยอดทั้งสี่เป็น 0; เรียง campaign_id ASC
  • ยอด views/clicks ไม่ได้เป็น distinct ข้าม batch; campaign ไม่มี ad ต้องไม่แสดง

Columns: campaign_id, name, views, clicks, orders, revenue

ข้อตกลงของข้อมูล

แต่ละตารางมีได้ 0–100000 แถว ข้อมูลอ้างอิงระหว่างตารางถูกต้อง (foreign key) รหัสเป็นจำนวนเต็มบวก (integer) และชื่อมีค่าเสมอ (text, NOT NULL) เว้นแต่ข้อกำหนดของข้อนั้นระบุเพิ่ม ในตารางตัวอย่าง NULL หมายถึงไม่มีค่า และ “ไม่มีแถว” หมายถึงไม่พบผลลัพธ์

เปิดแนวคิดทีละขั้น
  1. รวมยอดดูและคลิกให้เหลือหนึ่งแถวต่อโฆษณาก่อน (GROUP BY ad_id) แล้วรวมยอดสั่งซื้อและรายได้แยกอีกตารางด้วยวิธีเดียวกัน
  2. นำยอดสองฝั่งมาเชื่อมกับโฆษณา (LEFT JOIN) ตอนนี้แต่ละฝั่งเหลืออย่างมากหนึ่งแถวต่อโฆษณา ยอดจึงไม่ถูกนับซ้ำเพราะแถวจับคู่กันหลายครั้ง
  3. รวมยอดโฆษณาทั้งหมดของแต่ละ campaign แล้วแทนยอดที่ไม่มีด้วย 0 (SUM และ COALESCE)
  4. แสดง campaign ที่มียอดใดอย่างน้อยหนึ่งค่ามากกว่า 0 แล้วเรียงรหัส campaign จากน้อยไปมาก
เปิดเฉลย · จุดพลาด · เช็กก่อนส่ง

Reference SQL · PostgreSQL 16

WITH v AS (
  SELECT ad_id, SUM(views) AS views, SUM(clicks) AS clicks
  FROM view_stats GROUP BY ad_id
), o AS (
  SELECT ad_id, SUM(orders) AS orders, SUM(revenue) AS revenue
  FROM order_stats GROUP BY ad_id
), totals AS (
  SELECT c.campaign_id, c.name,
         COALESCE(SUM(v.views), 0) AS views,
         COALESCE(SUM(v.clicks), 0) AS clicks,
         COALESCE(SUM(o.orders), 0) AS orders,
         COALESCE(SUM(o.revenue), 0) AS revenue
  FROM campaigns c JOIN ads a ON a.campaign_id = c.campaign_id
  LEFT JOIN v ON v.ad_id = a.ad_id
  LEFT JOIN o ON o.ad_id = a.ad_id
  GROUP BY c.campaign_id, c.name
)
SELECT campaign_id, name, views, clicks, orders, revenue
FROM totals WHERE views > 0 OR clicks > 0 OR orders > 0 OR revenue > 0
ORDER BY campaign_id;

จุดพลาด

  • join raw child tables ได้ m×n แถว ทำให้ยอดคูณ
  • SUM(DISTINCT views) ทิ้ง batch ที่บังเอิญมียอดเท่ากัน
  • INNER JOIN ทั้งสอง stats ทำให้ ad ที่มีเพียงฝั่งเดียวหาย
  • ใช้ AND แทน OR ทำให้ campaign ที่มีเฉพาะ orders หาย

เช็กก่อนส่ง

  • อย่างน้อย 2×2 batches ของ ad เดียว
  • ยอดซ้ำที่ต้องบวก, stats ขาดฝั่ง, zero campaign, campaign ไม่มี ad

ยุบ stats ก่อน join ลด intermediate cardinality; อย่าแก้ fan-out ด้วย DISTINCT แบบครอบจักรวาล

ผู้ส่งต่อเนื่องและผู้ส่งสูงสุดรายวัน

ช่วงฝึก 2026-06-01 ถึง 2026-06-04 คืนทุกวันพร้อม retained_count (คนส่งอย่างน้อยหนึ่งครั้งทุกวันตั้งแต่วันเริ่มจนถึงวันนั้น) และ winner_id, winner_name ของผู้ส่งมากสุดในวันนั้น

ข้อกำหนด / Output

  • winner พิจารณาทุกคนที่ส่งวันนั้น ไม่จำกัดคน retained; จำนวนส่งเสมอเลือก member_id ต่ำสุด
  • วันที่ไม่มี submission ยังต้องคืนแถว retained_count=0 และ winner ทั้งสองเป็น SQL NULL
  • ละเลย submission นอกช่วง; การส่งหลายครั้งวันเดียวช่วย winner แต่ retained นับเป็นวันเดียว
  • members มี FK ถูกต้อง; เรียง day ASC; ผู้ที่ขาดวันก่อนกลับมา retained ไม่ได้

เปิดแนวคิดทีละขั้น
  1. สร้างรายการวันที่ 1–4 มิ.ย. ไว้ก่อน เพื่อให้คำตอบมีครบทุกวัน แม้วันนั้นไม่มีคนส่ง (calendar)
  2. ใช้เฉพาะข้อมูลในช่วงนี้ แล้วนับจำนวนครั้งที่แต่ละคนส่งในแต่ละวัน ให้เหลือหนึ่งแถวต่อคนต่อวัน (GROUP BY)
  3. หาคนที่ส่งต่อเนื่อง (retained): เรียงวันส่งของแต่ละคนแล้วใส่ลำดับ 1, 2, 3, … วันที่ 3 มิ.ย. ต้องเป็นวันส่งลำดับที่ 3 จึงแปลว่าส่งครบตั้งแต่วันแรก
  4. หาผู้ส่งมากที่สุดของแต่ละวัน (winner) จากทุกคน ไม่จำกัดเฉพาะคนส่งต่อเนื่อง ถ้าจำนวนส่งเท่ากัน เลือกรหัสคนน้อยกว่า (ROW_NUMBER)
  5. นำจำนวนคนส่งต่อเนื่องและผู้ชนะมาใส่ในรายการวัน (LEFT JOIN) วันไม่มีข้อมูลให้จำนวนเป็น 0 และชื่อกับรหัสผู้ชนะเป็น NULL
เปิดเฉลย · จุดพลาด · เช็กก่อนส่ง

Reference SQL · PostgreSQL 16

WITH calendar AS (
  SELECT DATE '2026-06-01' + i AS day FROM generate_series(0, 3) AS g(i)
), daily AS (
  SELECT submitted_on AS day, member_id, COUNT(*) AS submission_count
  FROM submissions
  WHERE submitted_on BETWEEN DATE '2026-06-01' AND DATE '2026-06-04'
  GROUP BY submitted_on, member_id
), progress AS (
  SELECT day, member_id,
         ROW_NUMBER() OVER (PARTITION BY member_id ORDER BY day) AS active_days
  FROM daily
), retained AS (
  SELECT day, COUNT(*) AS retained_count FROM progress
  WHERE active_days = day - DATE '2026-06-01' + 1
  GROUP BY day
), ranked AS (
  SELECT day, member_id,
         ROW_NUMBER() OVER (
           PARTITION BY day ORDER BY submission_count DESC, member_id
         ) AS position
  FROM daily
)
SELECT c.day, COALESCE(r.retained_count, 0) AS retained_count,
       w.member_id AS winner_id, m.name AS winner_name
FROM calendar c LEFT JOIN retained r ON r.day = c.day
LEFT JOIN ranked w ON w.day = c.day AND w.position = 1
LEFT JOIN members m ON m.member_id = w.member_id
ORDER BY c.day;

จุดพลาด

  • COUNT(*) raw submission แทน unique day ทำให้คนส่งหลายครั้งดูต่อเนื่อง
  • เลือก winner จาก retained ทำให้ Cy วันที่ 3 หาย
  • กรอง w.position=1 ใน WHERE ทำให้วันไม่มี winner หาย
  • ลืมตัดก่อนวันเริ่มทำให้เลขลำดับ active_days ผิด

เช็กก่อนส่ง

  • คนเริ่มช้าและกลับมาหลังขาดวัน
  • วันว่างกลางช่วง, winner ไม่ retained, tie และ submission นอกช่วง

daily ลดจำนวนแถวก่อน window; ช่วงใหญ่ควรใช้ calendar table และดู EXPLAIN ตามขนาดจริง
