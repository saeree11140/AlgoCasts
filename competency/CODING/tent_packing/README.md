# Tent Packing Problem – Coding Prep Guide

## 🚀 วิธีใช้งานโปรเจคนี้

1. แก้ไขโค้ดที่ไฟล์ `src/tentPacking.ts` ตามโจทย์หรือแนวทางที่ต้องการ
2. รันคำสั่ง `npm test` ใน terminal เพื่อทดสอบผลลัพธ์กับชุด test case ที่เตรียมไว้
3. ตรวจสอบผลลัพธ์ใน terminal ว่าผ่านทุก test case หรือไม่

## 🧩 Problem Statement

บริษัทจะจัดแคมป์พนักงาน มีพนักงานทั้งหมด `numPeople` คน  
และมีเต็นท์หลายขนาดในอาเรย์ `tentSizes` (เช่น `[2, 5, 6]`)  
เต็นท์แต่ละขนาดสามารถใช้ได้ไม่จำกัดจำนวน

**จงหาวิธีจัดคนลงเต็นท์ให้พอดีเป๊ะ (exact fit)**  
โดยใช้จำนวนเต็นท์ให้น้อยที่สุด

- ห้ามเกินความจุของเต็นท์
- ต้องจัดครบทุกคน
- ถ้าจัดพอดีไม่ได้ ให้ตอบ `-1`

## 📝 Guideline ในการแก้ปัญหา

### วิธี Greedy

เป็นวิธีที่เลือกเต็นท์ขนาดใหญ่ที่สุดเท่าที่จะใส่ได้ในแต่ละรอบ จนกว่าจะครบจำนวนคน

**ตัวอย่าง:**
จำนวนคน = 10, tentSizes = [2, 5, 6]
Greedy จะเลือก 6 ก่อน (เหลือ 4), จากนั้นเลือก 2 (เหลือ 2), แล้วเลือก 2 อีกใบ (ครบ 10)
ผลลัพธ์: [6, 2, 2] (ใช้ 3 ใบ)
แต่จริง ๆ แล้ว [5, 5] ใช้แค่ 2 ใบ ซึ่งดีกว่า

- ข้อดี: โค้ดง่ายและเร็ว
- ข้อเสีย: ไม่สามารถหาคำตอบที่ดีที่สุดได้ทุกกรณี เช่น บางกรณีต้องผสมเต็นท์ขนาดเล็กเพื่อให้ใช้จำนวนน้อยที่สุด
- ผลลัพธ์: จากการทดสอบด้วย test case ที่กำหนด (อาจไม่ครอบคลุมเท่ากับ test case จริง) Greedy สามารถผ่านได้ 9 จาก 10 test case (ตก 1 เคส)
  ตัวอย่างเคสที่ Greedy ไม่ผ่าน:
  จำนวนคน = 10, tentSizes = [6, 2, 5]
  Greedy จะเลือก 6 ก่อน แล้วตามด้วย 2+2 (รวม 3 ใบ) แต่คำตอบที่ดีที่สุดคือ 5+5 (2 ใบ)
  ดังนั้นควรใช้ Dynamic Programming (DP) หากต้องการคำตอบที่ดีที่สุดทุกกรณี

### วิธี Dynamic Programming (DP)

เป็นวิธีที่ใช้การบันทึกผลลัพธ์ย่อย (เช่น จำนวนเต็นท์ที่น้อยที่สุดสำหรับแต่ละจำนวนคน) แล้วนำมาสร้างคำตอบสำหรับจำนวนคนที่มากขึ้น

**ตัวอย่าง:**
จำนวนคน = 10, tentSizes = [2, 5, 6]
DP จะสร้างตาราง (array) สำหรับจำนวนคนแต่ละจำนวน (0 ถึง 10)
เช่น dp[0] = 0 (ไม่ต้องใช้เต็นท์), dp[2] = 1 (ใช้เต็นท์ 2), dp[5] = 1 (ใช้เต็นท์ 5), dp[6] = 1 (ใช้เต็นท์ 6)
จากนั้นค่อย ๆ เติม dp[7], dp[8], ... โดยดูว่าแต่ละจำนวนคนจะใช้เต็นท์ขนาดไหนต่อจากคำตอบย่อยที่ดีที่สุด
เช่น dp[7] = min(dp[7-2], dp[7-5], dp[7-6]) + 1
เมื่อถึง dp[10] จะพบว่าใช้เต็นท์ 5 สองใบ (dp[10] = dp[5] + 1 = 2)
และสามารถ reconstruct คำตอบย้อนกลับได้ว่าใช้เต็นท์ขนาด 5 สองใบ
ผลลัพธ์: [5, 5] (ใช้ 2 ใบ ซึ่งเป็น minimum)

- ข้อดี: สามารถหาคำตอบที่ดีที่สุด (minimum tents) ได้ทุกกรณี
- ข้อเสีย: โค้ดซับซ้อนกว่าและใช้หน่วยความจำมากขึ้น
- ผลลัพธ์: ผ่านทุก test case ได้ (คะแนนเต็ม)

### ข้อควรระวังในการเขียนโค้ด

- ควรลบขนาดเต็นท์ที่ซ้ำกัน (deduplicate) ก่อนคำนวณ เพื่อป้องกันผลลัพธ์ผิดพลาด
- ควรเรียง tentSizes จากมากไปน้อย (descending) เพื่อให้เลือกขนาดใหญ่ก่อน (ช่วยให้ Greedy และ DP ทำงานถูกต้องและเร็วขึ้น)
- อย่าลืมกรณีที่จัดคนลงเต๊นไม่ลงตัว → return -1
- ตอนทำข้อสอบจริง ควรเก็บ code ที่ทำงานได้เอาไว้ โดยการ comment code เอาไว้ก่อน แล้วก๊อปไปเริ่มทำ solution ใหม่ที่ดีกว่า เผื่อเวลาใกล้หมดจะได้สามารถย้อนกลับไปใช้ code เก่า submit ส่งได้ (ไม่งั้นอาจจะไม่ได้คะแนนเลย)

❗ หมายเหตุ: ชุด test case และ guideline ในโปรเจคนี้เป็นเพียงชุดเตรียมสอบ อาจไม่ตรงกับข้อสอบจริงหรือเงื่อนไขจริงทั้งหมด กรุณาอ่านและวิเคราะห์โจทย์จริงให้ละเอียดก่อนลงมือเขียนโค้ด

## Test Cases (Unit Test Set)

ด้านล่างคือ test cases ที่ควรครอบคลุมเวลาทำ unit test
สำหรับแต่ละเคส:

### Case 1: เคสพื้นฐาน จัดลงตัวง่าย

Input

```
10
[2, 5, 6]
```

Expected Output

```
2
[5, 5]
```

เหตุผล
5+5 = 10 ใช้แค่ 2 เต็นท์ ซึ่งน้อยที่สุด
คำตอบอื่นเช่น 6+2+2 = 10 ก็ถูกพอดีเหมือนกัน แต่ใช้ 3 เต็นท์ → ไม่ใช่คำตอบที่ต้องการ

➜ ใช้ตรวจว่าโค้ดหา minimum จริง ไม่ใช่แค่หา combination แรกที่ลงตัว

### Case 2: ไม่มีวิธีหารวมพอดี

Input

```
9
[5, 6]
```

Expected Output

```
-1
```

เหตุผล
ไม่มีทางบวกชุดไหนของ {2,5,6} แล้วได้ 9 พอดี

➜ ใช้ตรวจว่าโค้ด handle กรณี fail แล้วคืน -1 ถูกต้อง

### Case 3: ต้องผสมหลายขนาด

Input

```
11
[5, 6]
```

Expected Output

```
2
[5, 6]
```

เหตุผล
5+6=11 พอดี ใช้ 2 เต็นท์
อันนี้ทดสอบความสามารถของโค้ดในการ mix ขนาด ไม่ใช่แค่ spam ขนาดเดียว

### Case 4: ขนาดเต๊นท์ไม่เรียงลำดับ

Input

```
10
[6, 2, 5]
```

Expected Output

```
2
[5, 5]
```

เหตุผล
โค้ดต้องเลือก 5+5 ซึ่งใช้ 2 ใบ
ซึ่งใช้จำนวนเต๊นน้อยที่สุด

### Case 5: มี duplicate ใน tent size

Input

```
10
[2, 5, 5, 5, 6, 6]
```

Expected Output

```
2
[5, 5]
```

เหตุผล
ต้อง deduplicate sizes ก่อนคำนวณ ([2,5,6])
ต้องไม่พังเพราะไซส์ซ้ำ

### Case 6: ใช้ใบเดียวจบ

Input

```
8
[3, 5, 8]
```

Expected Output

```
1
[8]
```

เหตุผล
มีกลยุทธ์อื่นเช่น 3+5 ก็ได้ 8 (2 ใบ)
แต่เต็นท์ขนาด 8 ใบเดียวคือดีกว่า

### Case 7: หลายทางเลือก แต่ต้องเอาทางที่เต็นท์น้อยที่สุด

Input

```
8
[2, 3, 5]
```

Expected Output

```
2
[3, 5]
```

เหตุผล
สามารถจัดได้แบบ  
2+2+2+2=8  
3+3+2=8  
5+3=8  
ต้องตอบ 5+3=8 คือใบเต๊นน้อยสุด

### Case 8: จำนวนคนเล็ก (edge ต่ำสุด)

Input

```
1
[2, 3, 4]
```

Expected Output

```
-1
```

เหตุผล
ไม่มีเต็นท์ไหนจุ 1 คน และห้ามเหลือคนลอยอยู่

### Case 9: เต็นท์ไซส์เล็กสุดคือ 1 (ควร trivial ผ่าน)

Input

```
4
[1, 3, 5]
```

Expected Output

```
2
[1, 3]
```

เหตุผล
มีเต็นท์ 1 แปลว่ามีคำตอบเสมอ
แต่เราต้องหาคำตอบที่ใช้จำนวนน้อยสุด ไม่ใช่ 1+1+1+1 (4 ใบ)
1+3 = 4 ใช้ 2 ใบ ดีกว่า

### Case 10: ทดสอบจำนวนคนใหญ่ขึ้น

Input

```
14
[4, 6, 8]
```

Expected Output

```
2
[6, 8]
```

เหตุผล
6+8 = 14 ใช้ 2 ใบ
แม้ 4+4+6 = 14 ก็ถูก แต่ใช้ 3 ใบ → ไม่ดีเท่า
