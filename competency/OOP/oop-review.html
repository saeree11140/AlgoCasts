Class กับ object ต่างกันอย่างไร

ลองนึกถึงแบบฟอร์มสมัครสมาชิก class คือแบบฟอร์มเปล่า บอกว่ามีช่องอะไรให้กรอก (attribute) และฟอร์มทำอะไรได้ (method) ส่วน object คือฟอร์มแต่ละใบที่มีคนกรอกแล้ว แต่ละใบมีค่าของตัวเอง แก้ใบหนึ่งไม่กระทบอีกใบ

class Book {
    private final String title;      // attribute (field)
    private int copies;

    Book(String title, int copies) { // constructor
        this.title = title;
        this.copies = copies;
    }

    boolean borrow() {               // method
        if (copies == 0) return false;
        copies--;
        return true;
    }

    int getCopies() { return copies; }
}

public class Main {
    public static void main(String[] args) {
        Book b1 = new Book("Clean Code", 2);
        Book b2 = new Book("Refactoring", 1);
        b1.borrow();                               // เปลี่ยนเฉพาะ b1
        System.out.println(b1.getCopies() + " " + b2.getCopies());   // 1 1
    }
}

ข้อสังเกตหนึ่งที่คนมักพลาดคือ b1 กับ b2 เป็นตัวแปรที่เก็บ reference ชี้ไปยัง object ไม่ใช่ตัว object เอง เรื่องนี้จะกลับมาเป็นต้นเหตุของโจทย์ทายผลลัพธ์ในหัวข้อ 4

Constructor และ this

constructor ชื่อเหมือน class และไม่มี return type ถ้าเราไม่เขียนเลย Java จะเติม default constructor (ไม่รับ parameter) ให้ แต่พอเขียนเองแม้แต่ตัวเดียว ตัวที่เติมให้จะหายไป ถ้ายังอยากได้แบบไม่มี parameter ต้องเขียนเพิ่มเอง ส่วน this หมายถึง object ที่กำลังทำงานอยู่ ใช้แยก field ออกจาก parameter ที่ชื่อซ้ำกัน และใช้ this(...) เรียก constructor อีกตัวในคลาสเดียวกันได้

class Rectangle {
    private final double width, height;

    Rectangle(double width, double height) {
        this.width = width;
        this.height = height;
    }

    Rectangle(double side) { this(side, side); }   // ส่งต่อไปยัง constructor ตัวบน

    double area() { return width * height; }
}
บั๊กที่เจอบ่อยที่สุดเขียน balance = balance; ใน constructor แล้ว field ยังเป็น 0 เพราะทั้งสองฝั่งคือ parameter ตัวเดียวกัน ต้องเขียน this.balance = balance; ข้อสอบชอบหยิบเรื่องนี้มาถามเป็นโจทย์ทายผลลัพธ์

Encapsulation: ซ่อนข้อมูล เปิดเฉพาะพฤติกรรม

Beginner

Use encapsulation to group related data and behavior within classes.

เริ่มจากสถานการณ์ที่เจอจริง ทีมเปิด field total ของ Order เป็น public แล้วมีโค้ดสามสี่จุดเขียนค่าเข้าไปเอง วันหนึ่งยอดรวมติดลบในฐานข้อมูล ไล่หาต้นเหตุยากมากเพราะทุกจุดมีสิทธิ์เขียนได้ encapsulation แก้ปัญหานี้ด้วยการเอา "ข้อมูล" กับ "กฎที่ดูแลข้อมูลนั้น" ไว้ที่เดียวกัน แล้วปิดทางที่ไม่ผ่านกฎ มันไม่ได้แปลว่าใส่ private แล้วเขียน getter/setter ครบทุกตัว ถ้า setter รับค่าอะไรก็ได้ ก็เท่ากับเปิด public field ด้วยโค้ดที่ยาวขึ้น

class BankAccount {
    private long balanceSatang;                       // เก็บเป็นหน่วยย่อย ไม่ใช้ double กับเงิน

    BankAccount(long openingSatang) {
        if (openingSatang < 0) throw new IllegalArgumentException("opening balance must be >= 0");
        this.balanceSatang = openingSatang;
    }

    void deposit(long satang) {
        if (satang <= 0) throw new IllegalArgumentException("amount must be positive");
        balanceSatang += satang;
    }

    void withdraw(long satang) {
        if (satang <= 0) throw new IllegalArgumentException("amount must be positive");
        if (satang > balanceSatang) throw new IllegalStateException("insufficient funds");
        balanceSatang -= satang;
    }

    long balance() { return balanceSatang; }          // อ่านได้ แต่ไม่มี setBalance
}

สังเกตว่าไม่มี setBalance เลย ยอดเงินเปลี่ยนได้ผ่าน deposit กับ withdraw เท่านั้น และทั้งสองตรวจเงื่อนไขก่อนแตะข้อมูล ผู้เรียกจึงไม่มีทางทำให้บัญชีติดลบโดยไม่ผ่านด่านนี้ นี่คือสิ่งที่เรียกว่า invariant ของ class คือเงื่อนไขที่ต้องจริงเสมอไม่ว่าจะเรียกอะไรก่อนหลัง

ต่อให้ field เป็น private แล้ว ข้อมูลยังรั่วได้ถ้า getter คืน object ที่แก้ไขได้ หรือ constructor เก็บ reference ที่ผู้เรียกยังถืออยู่ คำว่า final ช่วยไม่ได้ เพราะมันล็อกแค่ตัวแปรไม่ให้ชี้ไปที่อื่น ไม่ได้ล็อกเนื้อใน object

import java.util.*;

class Team {
    private final List<String> members = new ArrayList<>();

    Team(Collection<String> initial) { members.addAll(initial); }   // copy เข้ามา ไม่เก็บ reference ของผู้เรียก

    void add(String name) { members.add(name); }

    List<String> members() { return List.copyOf(members); }          // คืนสำเนาที่แก้ไม่ได้
}

Immutable object

วิธีที่ปลอดภัยที่สุดคือทำให้ object เปลี่ยนค่าไม่ได้หลังสร้าง ไม่ต้องกังวลว่าใครจะแก้ ส่งข้ามส่วนต่าง ๆ ของโปรแกรมหรือข้าม thread ได้โดยไม่ต้อง lock หลักคือ field เป็น private final ไม่มี setter ถ้ารับหรือคืน object ที่แก้ได้ให้ copy และป้องกันไม่ให้ subclass มาเพิ่มสถานะที่เปลี่ยนได้ (ประกาศ class เป็น final) ตั้งแต่ Java 16 มี record ช่วยเขียน value object แบบนี้ได้สั้นลงมาก

record Money(long satang, String currency) {
    Money {                                           // compact constructor ใช้ตรวจค่าก่อนเก็บ
        if (satang < 0) throw new IllegalArgumentException("negative amount");
        java.util.Objects.requireNonNull(currency);
    }

    Money plus(Money other) {
        if (!currency.equals(other.currency)) throw new IllegalArgumentException("currency mismatch");
        return new Money(satang + other.satang, currency);   // สร้างตัวใหม่ ไม่แก้ตัวเดิม
    }
}

public class Main {
    public static void main(String[] args) {
        Money a = new Money(10_000, "THB");
        Money b = a.plus(new Money(2_550, "THB"));
        System.out.println(a + " " + b);       // Money[satang=10000, currency=THB] Money[satang=12550, currency=THB]
    }
}

ข้อควรระวัง field ของ record เป็น final แบบ shallow ถ้า field เป็น List ที่แก้ได้ เนื้อใน list ก็ยังแก้ได้อยู่ ต้อง copy ใน compact constructor ด้วยเช่นกัน

ภาษาอื่น

Python ไม่มี private ที่ภาษาบังคับจริง ธรรมเนียมคือชื่อที่ขึ้นต้นด้วย _ แปลว่า "อย่าแตะจากข้างนอก" ส่วน __ชื่อ ทำ name mangling เป็น _ClassName__ชื่อ เพื่อลดการชนชื่อกับ subclass ไม่ใช่การล็อก และใช้ @property เพิ่ม logic ตอนอ่านหรือเขียนได้โดยไม่เปลี่ยนวิธีเรียกใช้ TypeScript มี private กับ readonly แต่ตรวจเฉพาะตอนคอมไพล์ ถ้าต้องการให้ตัว runtime ห้ามจริงใช้ #field ของ JavaScript

Inheritance พื้นฐาน: extends, super และ override

Beginner

Apply basic inheritance to reuse and extend class functionality.

inheritance ให้ class ใหม่รับ attribute และ method จาก class เดิมมาใช้ แล้วเพิ่มหรือเปลี่ยนพฤติกรรมเฉพาะส่วนที่ต่าง ใน Java ใช้ extends และ class หนึ่งสืบทอดได้ตัวเดียว (single inheritance) ทุก class สืบทอดจาก java.lang.Object ไม่ทางตรงก็ทางอ้อม

class Employee {
    protected final String name;
    protected final double baseSalary;

    Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    double monthlyPay() { return baseSalary; }

    @Override public String toString() { return name + " earns " + monthlyPay(); }
}

class Manager extends Employee {
    private final double bonus;

    Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary);          // ต้องเรียก constructor ของ parent ก่อนเสมอ
        this.bonus = bonus;
    }

    @Override double monthlyPay() { return super.monthlyPay() + bonus; }
}

public class Main {
    public static void main(String[] args) {
        Employee e = new Manager("Ann", 50000, 8000);
        System.out.println(e);            // Ann earns 58000.0
    }
}

มีสามเรื่องที่ควรเห็นจากตัวอย่างนี้ เรื่องแรก super(name, baseSalary) เป็นการเรียก constructor ของ parent และใน Java 21 ต้องอยู่เป็นบรรทัดแรกของ constructor ถ้าไม่เขียน คอมไพเลอร์ใส่ super() ให้ ซึ่งจะ error ถ้า parent ไม่มี constructor แบบไม่รับ parameter เรื่องที่สอง @Override ไม่ได้ทำให้ทับได้ แต่ทำให้คอมไพเลอร์ตรวจว่าเราทับถูกตัวจริง ช่วยจับบั๊กชื่อหรือชนิด parameter ผิด เรื่องที่สาม toString() ใน Employee เรียก monthlyPay() และได้ 58000.0 ทั้งที่ตัวแปรเป็น Employee เพราะ method ถูกเลือกตามชนิด object จริง (Manager) ตอนรัน ซึ่งเป็นต้นทางของ polymorphism ที่จะลงลึกในหัวข้อ 5

ลำดับการสร้าง object

เมื่อสร้าง object ของ class ลูก constructor ของ parent ทำงานก่อนเสมอ ไล่จากบนสุดลงมา ถ้ามีสามชั้น A, B, C การ new C() จะรัน constructor ตามลำดับ A, B, C ถ้า parent ไม่มี constructor ที่ไม่รับ parameter ลูกต้องเรียก super(...) ด้วยค่าที่เหมาะสมเอง

ถาม "is-a" ก่อนใช้ inheritance

คำถามตรวจสอบง่าย ๆ คือ "ลูกเป็นพ่อจริงหรือไม่ และใช้แทนพ่อได้ทุกที่หรือไม่" SavingsAccount เป็น Account ผ่าน แต่ Car ไม่ใช่ Engine (Car มี Engine) และ Order ไม่ใช่ Customer เหตุผลที่ไม่ควรสืบทอดเพียงเพื่อยืมโค้ดมาใช้คือ ลูกจะผูกกับรายละเอียดของพ่อตลอดไป และ API ทั้งหมดของพ่อหลุดออกมาเป็นของลูกด้วย ระดับ Intermediate จะกลับมาที่เรื่องนี้พร้อมทางเลือกอย่าง composition

กฎสั้น ๆ ที่ควรจำ final class สืบทอดไม่ได้ · final method ทับไม่ได้ · constructor ไม่ถูกสืบทอด · private member ของ parent ไม่สามารถเรียกตรง ๆ จากลูกได้ · method ที่เป็น static ถูก hide ไม่ใช่ override

ในภาษาอื่น Python รองรับ multiple inheritance ผ่านลำดับการค้นหาที่เรียกว่า MRO (Method Resolution Order) ส่วน TypeScript กับ Java ให้ extends ได้ตัวเดียวเช่นกัน และใช้ interface เป็นทางออกเมื่อต้องการหลายสัญญา

ตัวแปรเก็บ reference ไม่ใช่ object

เมื่อเขียน Counter c2 = c1; ไม่ได้มี object ใหม่เกิดขึ้น มีแค่ตัวแปรที่สองชี้ไปที่ object เดิม ใครแก้ผ่านตัวแปรไหน อีกตัวก็เห็นด้วย เรื่องนี้ต่อเนื่องไปยังการส่ง argument Java ส่งทุกอย่างแบบ pass-by-value แต่สำหรับ object ค่าที่ถูกคัดลอกคือ reference

public class Main {
    static void change(StringBuilder sb, int n) {
        sb.append("!");                  // แก้ object เดิมผ่าน reference ที่คัดลอกมา มีผลถึงผู้เรียก
        n = 99;                          // แก้สำเนาของ primitive ไม่มีผลถึงผู้เรียก
        sb = new StringBuilder("new");   // ทำให้ตัวแปรในเมธอดชี้ที่อื่น ผู้เรียกไม่เห็น
    }

    public static void main(String[] args) {
        StringBuilder s = new StringBuilder("hi");
        int x = 1;
        change(s, x);
        System.out.println(s + " " + x);   // hi! 1
    }
}

== กับ equals()

== กับ object เทียบ reference ว่าเป็นตัวเดียวกันหรือไม่ ส่วน equals() เทียบ "ความเท่ากันเชิงความหมาย" ตามที่ class นั้นนิยามไว้ ถ้าไม่ override equals() จะเหมือน == ตัวอย่างคลาสสิกคือ String literal ที่ถูกแชร์จาก string pool

public class Main {
    public static void main(String[] args) {
        String a = new String("java");
        String b = new String("java");
        String c = "java";
        String d = "java";
        System.out.println((a == b) + " " + (c == d) + " " + a.equals(b));   // false true true
    }
}

equals และ hashCode ต้องไปด้วยกัน

สัญญาของ Object บอกว่าถ้า a.equals(b) เป็นจริง hashCode() ของสองตัวต้องเท่ากัน คอลเลกชันแบบ hash (HashSet, HashMap) ใช้ hashCode หา bucket ก่อนแล้วค่อยเรียก equals ถ้า override แค่ equals ตัวที่ "เท่ากัน" อาจอยู่คนละ bucket จึงไม่ถูกมองว่าซ้ำ ใช้ field ที่ไม่เปลี่ยนค่าเป็นฐานของทั้งสอง method ถ้า field เปลี่ยนหลังเอาเข้า set object จะ "หายไป" จากการค้นหา (ดูโจทย์ในหัวข้อ 9)

import java.util.Objects;

class Point {
    private final int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }

    @Override public boolean equals(Object o) {
        return o instanceof Point p && x == p.x && y == p.y;
    }
    @Override public int hashCode() { return Objects.hash(x, y); }
    @Override public String toString() { return "Point(" + x + "," + y + ")"; }
}

สังเกตว่า parameter ของ equals ต้องเป็น Object ถ้าเขียนเป็น equals(Point p) จะเป็นการ overload ไม่ใช่ override และ List.contains หรือ HashSet จะไม่เรียกตัวนั้น เพราะเรียก equals(Object) เสมอ ใส่ @Override ไว้จะช่วยจับได้ทันที

ลำดับการ initialize

เมื่อ class ถูกโหลดครั้งแรก static block รัน (ครั้งเดียว) จากนั้นทุกครั้งที่สร้าง object: constructor ของ parent ทำงานก่อน แล้ว instance initializer กับ field initializer ของ class นั้น แล้วจึงถึงโค้ดใน constructor ของ class นั้น ถ้าเจอโจทย์ที่พิมพ์ข้อความจาก static block, instance block และ constructor ให้ไล่ตามลำดับนี้ จะไม่หลง

เทคนิคอ่านโค้ดทายผลลัพธ์

ลองไล่เป็นลำดับ ข้อแรก แยก "ชนิดของตัวแปร" ออกจาก "ชนิดของ object จริง" ข้อสอง overload เลือกตอนคอมไพล์จากชนิดตัวแปร ส่วน override เลือกตอนรันจากชนิด object จริง ข้อสาม static และ field ไม่มี polymorphism ข้อสี่ ไล่ลำดับ initialize ตามที่ว่าไว้ ข้อห้า ตัวแปรสองตัวอาจชี้ object เดียวกัน ถ้าเห็นโค้ดที่ = ระหว่าง object ให้ถามตัวเองว่าคัดลอก reference หรือสร้างตัวใหม่

ใน Python มีกับดักเรื่อง mutable default argument: def __init__(self, items=[]) สร้าง list ครั้งเดียวตอนนิยามฟังก์ชัน ทุก object ที่ไม่ส่งค่ามาจะใช้ list ตัวเดียวกัน วิธีแก้คือใช้ items=None แล้วสร้างใหม่ภายใน method

Design and implement class hierarchies using inheritance and polymorphism.

polymorphism คือความสามารถที่โค้ดเดียวกันทำงานกับ object หลายชนิดได้ โดยแต่ละชนิดตอบสนองตามแบบของตัวเอง ประโยชน์ที่เห็นชัดที่สุดคือผู้เรียกพึ่งพาแค่สัญญา ไม่ต้องรู้ชนิดจริง เพิ่มชนิดใหม่ได้โดยไม่แก้โค้ดเดิม

import java.util.*;

interface Shape { double area(); }
record Circle(double r) implements Shape { public double area() { return Math.PI * r * r; } }
record Rect(double w, double h) implements Shape { public double area() { return w * h; } }

public class Main {
    static double totalArea(List<? extends Shape> shapes) {
        double total = 0;
        for (Shape s : shapes) total += s.area();   // ไม่รู้และไม่ต้องรู้ว่าเป็นชนิดไหน
        return total;
    }

    public static void main(String[] args) {
        System.out.printf("%.2f%n", totalArea(List.of(new Circle(1), new Rect(2, 3))));   // 9.14
    }
}

ถ้าวันหน้าต้องเพิ่ม Triangle ก็แค่เขียน class ใหม่ที่ implements Shape ฟังก์ชัน totalArea ไม่ต้องแตะเลย

กับดักสี่อย่างในโปรแกรมเดียว

โค้ดต่อไปนี้รวมเรื่องที่ข้อสอบชอบถามไว้ด้วยกัน ลองเดาผลลัพธ์แต่ละบรรทัดก่อนอ่านคอมเมนต์

class P {
    String name = "P";
    static String kind() { return "P.kind"; }
    String who() { return "P.who"; }
    P() { init(); }
    void init() { }
}

class C extends P {
    String name = "C";
    String tag = "ready";
    static String kind() { return "C.kind"; }
    @Override String who() { return "C.who"; }
    @Override void init() { System.out.println("init sees tag=" + tag); }
}

public class Main {
    public static void main(String[] args) {
        P ref = new C();                                 // พิมพ์ init sees tag=null
        System.out.println(ref.who());                   // C.who   method เลือกตาม object จริง
        System.out.println(ref.name);                    // P       field เลือกตามชนิดตัวแปร
        System.out.println(P.kind() + " " + C.kind());   // P.kind C.kind   static ถูก hide ไม่ใช่ override
    }
}

บรรทัดแรกที่พิมพ์ tag=null เกิดเพราะ constructor ของ P เรียก init() ซึ่งถูกทับโดย C ตอนนั้น field ของ C ยังไม่ถูกกำหนดค่า ข้อสรุปในงานจริงคือ อย่าเรียก method ที่ทับได้ภายใน constructor ถ้าจำเป็นต้องทำงานตอนสร้าง ให้ใช้ method ที่ final หรือ private หรือใช้ factory method

Upcast, downcast และ instanceof

การเก็บ object ของ subclass ไว้ในตัวแปรชนิด parent (upcast) ทำได้เสมอและปลอดภัย ส่วนการแปลงกลับ (downcast) คอมไพเลอร์ยอมให้เขียนแต่ JVM ตรวจตอนรัน ถ้าชนิดจริงไม่ตรงจะเกิด ClassCastException ทางที่ดีคือตรวจด้วย instanceof ก่อน ซึ่งตั้งแต่ Java 16 เขียนรวมกับการประกาศตัวแปรได้ และถ้าพบว่าต้อง downcast บ่อย ๆ มักเป็นสัญญาณให้ทบทวนว่าควรเพิ่ม method ใน parent แทน

Object o = "hello";

    System.out.println(s.toUpperCase());       // HELLO
}

inheritance ตอบคำถามว่า "X เป็น Y หรือไม่" (is-a) ส่วนความสัมพันธ์ "X มี Y" (has-a) ใช้การประกอบ object เข้าด้วยกัน ซึ่งแบ่งได้ตามระดับความผูกพัน

Composition พร้อม delegation

ตัวอย่างต่อไปนี้ Car ไม่ได้สืบทอด Engine แต่ถือ Engine ไว้ แล้วส่งงานต่อ (delegate) ให้ ผลคือเปลี่ยนชนิดเครื่องยนต์ได้โดยไม่ต้องสร้าง class ใหม่อย่าง ElectricCar หรือ PetrolCar และทดสอบ Car ด้วย engine ปลอมได้

interface Engine { String start(); }
class Petrol implements Engine { public String start() { return "vroom"; } }
class Electric implements Engine { public String start() { return "hum"; } }

class Car {
    private final Engine engine;
    Car(Engine engine) { this.engine = engine; }
    String start() { return engine.start(); }       // delegation
}

public class Main {
    public static void main(String[] args) {
        System.out.println(new Car(new Petrol()).start());     // vroom
        System.out.println(new Car(new Electric()).start());   // hum
    }
}

Aggregation กับปัญหา aliasing

เมื่อ class รับ collection จากภายนอกมาเก็บ (aggregation) ผู้เรียกยังถือ reference เดิมอยู่ ใครแก้ list ภายนอก ข้อมูลใน class ก็เปลี่ยนตามโดยไม่รู้ตัว ถ้า class ต้องการเป็นเจ้าของข้อมูลจริง ให้ copy ตั้งแต่ constructor (defensive copy)

import java.util.*;

class Course {
    final List<String> students;
    Course(List<String> students) { this.students = new ArrayList<>(students); }   // copy; ถ้าไม่ copy จะได้ 2
}

public class Main {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>(List.of("A"));
        Course c = new Course(list);
        list.add("B");
        System.out.println(c.students.size());    // 1
    }
}

}

class Sales extends Report {
    String body() { return "sales"; }
}

public class Main {
    public static void main(String[] args) {

}

Interface, default method และปัญหา diamond

ตั้งแต่ Java 8 interface มี default method ได้ ทำให้ขยาย interface ที่เผยแพร่ไปแล้วโดยไม่ทำให้ผู้ implement เดิมพัง ข้อแลกเปลี่ยนคือถ้า class implements สอง interface ที่มี default method ชื่อเดียวกัน คอมไพเลอร์ไม่เดาให้ ต้อง override เองและเลือกได้ว่าจะเรียกตัวไหนด้วย InterfaceName.super.method()

interface A { default String hi() { return "A"; } }
interface B { default String hi() { return "B"; } }

class C implements A, B {
    public String hi() { return A.super.hi() + B.super.hi(); }   // ถ้าไม่ override จะคอมไพล์ไม่ผ่าน
}

public class Main {
    public static void main(String[] args) {
        System.out.println(new C().hi());    // AB

class Booking {
    private final String guest;
    private final int guests;
    private final String roomType;
    private final boolean breakfast;

    private Booking(Builder b) {
        this.guest = b.guest;
        this.guests = b.guests;
        this.roomType = b.roomType;
        this.breakfast = b.breakfast;
    }

    static Builder builder(String guest) { return new Builder(guest); }

    static class Builder {
        private final String guest;
        private int guests = 1;
        private String roomType = "standard";
        private boolean breakfast;

        private Builder(String guest) { this.guest = guest; }
        Builder guests(int n) { this.guests = n; return this; }
        Builder roomType(String t) { this.roomType = t; return this; }
        Builder breakfast(boolean b) { this.breakfast = b; return this; }

        Booking build() {
            if (guests < 1) throw new IllegalStateException("guests must be >= 1");
            return new Booking(this);
        }
    }

    @Override public String toString() {
        return "Booking[" + guest + ", " + guests + ", " + roomType + ", " + breakfast + "]";
    }
}

public class Main {
    public static void main(String[] args) {
        Booking b = Booking.builder("Ann").guests(2).roomType("deluxe").breakfast(true).build();
        System.out.println(b);    // Booking[Ann, 2, deluxe, true]
    }
}

interface Discount { double apply(double price); }

class Cart {
    private Discount discount;
    Cart(Discount d) { this.discount = d; }
    void setDiscount(Discount d) { this.discount = d; }          // สลับตอนรันได้
    double total(double price) { return discount.apply(price); }
}

public class Main {
    public static void main(String[] args) {
        Cart cart = new Cart(p -> p * 0.9);
        System.out.println(cart.total(200));     // 180.0
        cart.setDiscount(p -> p - 50);
        System.out.println(cart.total(200));     // 150.0
    }
}

class Sms implements Notifier { public String send(String m) { return "sms:" + m; } }

class NotifierFactory {
    private final Map<String, Supplier<Notifier>> registry = new HashMap<>();

    void register(String type, Supplier<Notifier> maker) { registry.put(type, maker); }

    Notifier create(String type) {
        Supplier<Notifier> maker = registry.get(type);
        if (maker == null) throw new IllegalArgumentException("unknown notifier: " + type);   // ล้มเร็ว บอกค่าที่ผิด
        return maker.get();
    }
}

public class Main {
    public static void main(String[] args) {
        NotifierFactory f = new NotifierFactory();
        f.register("email", Email::new);
        f.register("sms", Sms::new);
        System.out.println(f.create("sms").send("hi"));     // sms:hi
    }
}

Observer: subject แจ้งผู้สนใจโดยไม่ต้องรู้จักพวกเขา

Observer ใช้เมื่อสถานะของ object หนึ่งเปลี่ยนแล้วมีหลายส่วนต้องรู้ เช่น ราคาหุ้นเปลี่ยนแล้วกราฟ การแจ้งเตือน และ log ต้องอัปเดต subject รู้จักแค่ interface ของผู้ฟัง เพิ่มผู้ฟังใหม่ได้โดยไม่แก้ subject ข้อควรระวังในโค้ดจริงมีสามเรื่อง ข้อแรก ห้ามแก้ list ผู้ฟังระหว่างวนอ่านโดยตรง (เช่น ผู้ฟังยกเลิกตัวเองระหว่างถูกแจ้ง) จะเจอ ConcurrentModificationException ให้วนบนสำเนา ข้อสอง ผู้ฟังที่ throw exception ตัวหนึ่งไม่ควรทำให้ตัวที่เหลือไม่ได้รับแจ้ง ข้อสาม ต้องมีวิธียกเลิกการสมัคร ไม่เช่นนั้น subject ที่อายุยาวจะถือ reference ไปยังผู้ฟังที่อายุสั้นกว่าจน GC เก็บคืนไม่ได้ (lapsed listener)

import java.util.*;

interface Listener { void onEvent(String e); }

class Bus {
    private final List<Listener> listeners = new ArrayList<>();

    void subscribe(Listener l) { listeners.add(l); }
    void unsubscribe(Listener l) { listeners.remove(l); }

    void publish(String e) {
        for (Listener l : List.copyOf(listeners)) {     // วนบนสำเนา ยกเลิกระหว่างวนได้
            try { l.onEvent(e); }
            catch (RuntimeException ex) { System.err.println("listener failed: " + ex.getMessage()); }
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Bus bus = new Bus();
        Listener[] once = new Listener[1];
        once[0] = e -> { System.out.println("once"); bus.unsubscribe(once[0]); };
        bus.subscribe(once[0]);
        bus.subscribe(e -> System.out.println("L2"));
        bus.subscribe(e -> System.out.println("L3"));
        bus.publish("x");    // once, L2, L3
        bus.publish("y");    // L2, L3
    }
}

Java 17 เพิ่ม sealed ให้ระบุว่า class หรือ interface นี้อนุญาตให้ชนิดไหนสืบทอดได้บ้าง เมื่อรวมกับ record และ pattern matching ใน switch (Java 21) คอมไพเลอร์ตรวจได้ว่าจัดการครบทุกชนิดหรือยัง ถ้ามีคนเพิ่มชนิดใหม่แล้วลืมแก้ switch จะ error ตั้งแต่คอมไพล์ ไม่ใช่มาพังตอนรัน เหมาะกับโดเมนที่ชุดชนิดย่อยปิดและแน่นอน (เช่น ผลลัพธ์สำเร็จหรือล้มเหลว) ส่วนโดเมนที่ผู้อื่นต้องเพิ่มชนิดได้เอง ให้ใช้ interface แบบเปิดต่อไป

sealed interface Shape permits Circle, Rect, Tri { }
record Circle(double r) implements Shape { }
record Rect(double w, double h) implements Shape { }
record Tri(double b, double h) implements Shape { }

public class Main {
    static double area(Shape s) {
        return switch (s) {                                   // ไม่มี default ได้ เพราะ sealed
            case Circle(double r) -> Math.PI * r * r;         // record pattern (Java 21)
            case Rect(double w, double h) -> w * h;
            case Tri(double b, double h) -> 0.5 * b * h;
        };
    }

    public static void main(String[] args) {
        System.out.println(area(new Rect(2, 3)) + " " + area(new Tri(4, 5)));    // 6.0 10.0
    }
}

dependency ที่ซ่อนง่ายที่สุดคือเวลา สุ่ม ไฟล์ และเครือข่าย LocalDate.now() ที่เรียกตรง ๆ ทำให้เทสต์ให้ผลต่างกันตามวันที่รัน ทางแก้คือรับ java.time.Clock เข้ามาทาง constructor

import java.time.*;
import java.time.temporal.ChronoUnit;

class LateFee {
    private final Clock clock;
    LateFee(Clock clock) { this.clock = clock; }

    long feeBaht(LocalDate dueDate) {
        long daysLate = ChronoUnit.DAYS.between(dueDate, LocalDate.now(clock));
        return daysLate > 30 ? (daysLate - 30) * 10 : 0;       // เริ่มปรับหลังเกิน 30 วัน วันละ 10 บาท
    }
}

public class Main {
    public static void main(String[] args) {
        Clock fixed = Clock.fixed(Instant.parse("2026-03-15T00:00:00Z"), ZoneOffset.UTC);
        System.out.println(new LateFee(fixed).feeBaht(LocalDate.of(2026, 1, 1)));   // 430
    }
}

@Test

}

ความต่างของ polymorphism ในแต่ละภาษา

Python ใช้ duck typing: ถ้า object มี method ที่ต้องการก็ใช้แทนกันได้ โดยไม่ต้องมี base class ร่วม (ใช้ typing.Protocol ถ้าอยากให้ตัวตรวจชนิดช่วยเช็กรูปร่างล่วงหน้า) TypeScript ใช้ structural typing ตอนคอมไพล์ แต่ชนิดถูกลบหลังคอมไพล์ จึงเช็กชนิดตอนรันด้วย interface ไม่ได้ ส่วน Java กับ C# ใช้ nominal typing ต้องประกาศ implements ชัดเจน

    def area(self):
        return 1

class Sq:
    def __init__(self, s):
        self.s = s
    def area(self):
        return self.s ** 2

    return sum(s.area() for s in shapes)

interface HasArea { area(): number }

class Sq {
  constructor(private s: number) {}
  area(): number { return this.s ** 2 }
}

function total(items: HasArea[]): number {
  return items.reduce((sum, x) => sum + x.area(), 0)
}

import java.util.*;

class Book {
    private int owned;
    private int available;

    Book(int copies) { owned = copies; available = copies; }

    void addCopies(int n) { owned += n; available += n; }

    boolean borrow() {
        if (available == 0) return false;
        available--;
        return true;
    }

    String giveBack() {
        if (available == owned) return "INVALID";   // คืนเกินจำนวนที่ยืมไป
        available++;
        return "OK";
    }

    int available() { return available; }
}

class Library {
    private final Map<String, Book> books = new HashMap<>();

    void add(String title, int copies) {
        books.computeIfAbsent(title, t -> new Book(0)).addCopies(copies);
    }

    String borrow(String title) {
        Book b = books.get(title);
        return (b != null && b.borrow()) ? "OK" : "UNAVAILABLE";
    }

    String giveBack(String title) {
        Book b = books.get(title);
        return b == null ? "UNKNOWN" : b.giveBack();
    }

    int stock(String title) {
        Book b = books.get(title);
        return b == null ? 0 : b.available();
    }
}

public class Solution {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = Integer.parseInt(in.nextLine().trim());
        Library lib = new Library();
        for (int i = 0; i < n; i++) {
            String[] p = in.nextLine().trim().split("\\s+");
            switch (p[0]) {
                case "ADD" -> lib.add(p[1], Integer.parseInt(p[2]));
                case "BORROW" -> System.out.println(lib.borrow(p[1]));
                case "RETURN" -> System.out.println(lib.giveBack(p[1]));
                case "STOCK" -> System.out.println(lib.stock(p[1]));
                default -> throw new IllegalArgumentException("bad command: " + p[0]);
            }
        }
    }
}

import java.util.*;

abstract class Employee {
    private final String name;
    Employee(String name) { this.name = name; }
    String name() { return name; }
    abstract double pay();
}

class Salaried extends Employee {
    private final double monthly;
    Salaried(String name, double monthly) { super(name); this.monthly = monthly; }
    double pay() { return monthly; }
}

class Hourly extends Employee {
    private static final double REGULAR_HOURS = 160;
    private final double rate, hours;
    Hourly(String name, double rate, double hours) { super(name); this.rate = rate; this.hours = hours; }
    double pay() {
        double regular = Math.min(hours, REGULAR_HOURS) * rate;
        double overtime = Math.max(hours - REGULAR_HOURS, 0) * rate * 1.5;
        return regular + overtime;
    }
}

class Commission extends Employee {
    private final double base, sales, ratePercent;
    Commission(String name, double base, double sales, double ratePercent) {
        super(name);
        this.base = base; this.sales = sales; this.ratePercent = ratePercent;
    }
    double pay() { return base + sales * ratePercent / 100; }
}

public class Solution {
    static Employee parse(String line) {
        String[] p = line.trim().split("\\s+");
        return switch (p[0]) {
            case "SALARIED" -> new Salaried(p[1], Double.parseDouble(p[2]));
            case "HOURLY" -> new Hourly(p[1], Double.parseDouble(p[2]), Double.parseDouble(p[3]));
            case "COMMISSION" -> new Commission(p[1], Double.parseDouble(p[2]),
                                                Double.parseDouble(p[3]), Double.parseDouble(p[4]));
            default -> throw new IllegalArgumentException("unknown type: " + p[0]);
        };
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = Integer.parseInt(in.nextLine().trim());
        List<Employee> list = new ArrayList<>();
        for (int i = 0; i < n; i++) list.add(parse(in.nextLine()));

        list.sort(Comparator.comparingDouble(Employee::pay).reversed().thenComparing(Employee::name));

        double total = 0;
        for (Employee e : list) {
            System.out.println(String.format(Locale.US, "%s %.2f", e.name(), e.pay()));
            total += e.pay();
        }
        System.out.println(String.format(Locale.US, "TOTAL %.2f", total));
    }

อ่าน n แล้วอ่านคำสั่ง n บรรทัด

เก็บผู้สมัครไว้ใน Map<topic, List<Sub>> ตอน publish คัดลอก list ก่อนเรียงและวน เพื่อให้ผู้ฟังแก้รายชื่อระหว่างถูกแจ้งได้โดยไม่เจอ ConcurrentModificationException ลำดับ "ก่อนหลัง" ตัดสินด้วยหมายเลข seq ที่เพิ่มขึ้นทุกครั้งที่สมัคร ไม่ใช้ตำแหน่งใน list เพราะตำแหน่งเปลี่ยนเมื่อมีคนยกเลิก

import java.util.*;

interface Listener { void onMessage(String topic, String message); }

class Subscriber implements Listener {
    private final String id;
    Subscriber(String id) { this.id = id; }
    public void onMessage(String topic, String message) { System.out.println(id + ":" + message); }
}

class EventBus {
    private record Sub(Listener listener, String id, int priority, long seq) { }

    private final Map<String, List<Sub>> topics = new HashMap<>();
    private long counter = 0;

    void subscribe(String topic, String id, int priority, Listener listener) {
        List<Sub> subs = topics.computeIfAbsent(topic, t -> new ArrayList<>());
        for (Sub s : subs) if (s.id().equals(id)) return;            // สมัครซ้ำ ไม่ทำอะไร
        subs.add(new Sub(listener, id, priority, counter++));
    }

    void unsubscribe(String topic, String id) {
        List<Sub> subs = topics.get(topic);
        if (subs != null) subs.removeIf(s -> s.id().equals(id));
    }

    void publish(String topic, String message) {
        List<Sub> snapshot = new ArrayList<>(topics.getOrDefault(topic, List.of()));   // วนบนสำเนา
        snapshot.sort(Comparator.comparingInt(Sub::priority).reversed().thenComparingLong(Sub::seq));
        for (Sub s : snapshot) s.listener().onMessage(topic, message);
    }
}

public class Solution {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = Integer.parseInt(in.nextLine().trim());
        EventBus bus = new EventBus();
        for (int i = 0; i < n; i++) {
            String[] p = in.nextLine().trim().split("\\s+");
            switch (p[0]) {
                case "SUB" -> bus.subscribe(p[2], p[1], Integer.parseInt(p[3]), new Subscriber(p[1]));
                case "UNSUB" -> bus.unsubscribe(p[2], p[1]);
                case "PUB" -> bus.publish(p[1], p[2]);
                default -> throw new IllegalArgumentException("bad command: " + p[0]);
            }
        }
    }
}

แต่ละกฎเป็น lambda ที่ implements DiscountRule ซึ่งเป็น functional interface ส่วนการ "เลือกชนิด" เก็บใน Map ของวิธีสร้าง นี่คือ Strategy ร่วมกับ factory แบบ registry ที่คุยกันในหัวข้อ 10 เพิ่มชนิดใหม่คือเพิ่มบรรทัดเดียวใน constructor ของ RuleFactory ข้อควรระวังคือกฎ FIXED ที่ราคาหลังลดต่ำกว่า 0 ต้องครอบด้วย Math.max(0, ...) ซึ่งเป็นกรณีขอบที่ตัวอย่างที่สองทดสอบอยู่

import java.util.*;
import java.util.function.Function;

interface DiscountRule { double apply(double price); }

class RuleFactory {
    private final Map<String, Function<Double, DiscountRule>> kinds = new HashMap<>();

    RuleFactory() {
        kinds.put("PERCENT", p -> price -> price * (100 - p) / 100);
        kinds.put("FIXED", x -> price -> Math.max(0, price - x));
        // เพิ่มชนิดใหม่ = เพิ่มอีกหนึ่งบรรทัดตรงนี้ ไม่ต้องแก้ส่วนอ่านคำสั่ง
    }

    DiscountRule create(String kind, double param) {
        Function<Double, DiscountRule> maker = kinds.get(kind);
        if (maker == null) throw new IllegalArgumentException("unknown kind: " + kind);
        return maker.apply(param);
    }
}

public class Solution {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = Integer.parseInt(in.nextLine().trim());
        RuleFactory factory = new RuleFactory();
        Map<String, DiscountRule> rules = new HashMap<>();

        for (int i = 0; i < n; i++) {
            String[] p = in.nextLine().trim().split("\\s+");
            if (p[0].equals("RULE")) {
                rules.put(p[1], factory.create(p[2], Double.parseDouble(p[3])));
            } else if (p[0].equals("PRICE")) {
                DiscountRule r = rules.get(p[1]);
                System.out.println(r == null ? "UNKNOWN_RULE"
                                             : String.format(Locale.US, "%.2f", r.apply(Double.parseDouble(p[2]))));
            }
        }
    }
}

โค้ดนี้คอมไพล์ผ่านแต่มีปัญหาหลายจุด ลองอ่านแล้วบอกว่าตัวอย่างใน main แต่ละบรรทัดจะให้ผลอะไร และเพราะอะไร จากนั้นแก้ให้ถูก มีปัญหาที่ตั้งใจใส่ไว้ห้าจุด

import java.util.*;

class Product {
    final String sku;
    final double price;

    Product(String sku, double price) { this.sku = sku; this.price = price; }

    public boolean equals(Product other) { return sku.equals(other.sku); }      // (1)
}

class Cart {
    private final List<Product> items = new ArrayList<>();

    Cart() { reset(); }                                                        // (3)
    void reset() { items.clear(); }

    void add(Product p) { if (!items.contains(p)) items.add(p); }

    List<Product> getItems() { return items; }                                 // (2)

    double total() {                                                           // (4)
        double t = 0;
        for (Product p : items) t += p.price;
        return t;
    }
}

class AuditedCart extends Cart {
    private final List<String> log = new ArrayList<>();
    @Override void reset() { super.reset(); log.add("reset"); }
}

public class Main {
    public static void main(String[] args) {
        Cart c = new Cart();
        c.add(new Product("A", 0.1));

        System.out.println(c.total());               // 0.30000000000000004
        c.getItems().clear();                        // ล้างตะกร้าจากภายนอกได้

}

(1) equals(Product)เป็น overload ไม่ใช่ override เพราะ parameter เป็น Product ไม่ใช่ Object List.contains เรียก equals(Object) ของ Object ที่เทียบ reference จึงไม่เจอตัวซ้ำ ได้ 3 ชิ้นเขียน equals(Object) ใส่ @Override (ถ้าใส่ตั้งแต่แรกคอมไพเลอร์จะฟ้องทันที)
ไม่มี hashCodeแม้แก้ equals แล้ว ถ้าเอา Product ไปใส่ HashSet หรือเป็น key ของ HashMap ก็ยังหาไม่เจอ เพราะ hash ตามที่อยู่ objectoverride hashCode ให้ใช้ field ชุดเดียวกับ equals
(2) getItems()คืน list ภายในตรง ๆ ผู้เรียกจึงล้างหรือแก้ตะกร้าได้ข้ามกฎของ Cart (บรรทัดที่สามพิมพ์ 0)คืนสำเนาที่แก้ไม่ได้ด้วย List.copyOf หรือ Collections.unmodifiableList และเปิด method พฤติกรรมที่ตั้งใจ เช่น clear()

(4) double กับเงิน0.1 + 0.1 + 0.1 ได้ 0.30000000000000004 เพราะเลขทศนิยมฐานสองแทนค่าบางตัวไม่ตรงเก็บเป็นสตางค์ด้วย long หรือใช้ BigDecimal (สร้างจาก String ไม่ใช่จาก double)

import java.util.*;

class Product {
    private final String sku;
    private final long priceSatang;

    Product(String sku, long priceSatang) {
        this.sku = Objects.requireNonNull(sku);
        this.priceSatang = priceSatang;
    }

    long priceSatang() { return priceSatang; }

    @Override public boolean equals(Object o) {
        return o instanceof Product p && sku.equals(p.sku);
    }
    @Override public int hashCode() { return sku.hashCode(); }
}

class Cart {
    private final List<Product> items = new ArrayList<>();

    void add(Product p) { if (!items.contains(p)) items.add(p); }

    List<Product> items() { return List.copyOf(items); }        // คืนสำเนาที่แก้ไม่ได้

    long totalSatang() {
        long t = 0;
        for (Product p : items) t += p.priceSatang();
        return t;
    }

    void clear() { items.clear(); }                              // เปิดเป็นพฤติกรรมที่ตั้งใจ ไม่ใช่ช่องรั่ว
}

class AuditedCart extends Cart {
    private final List<String> log = new ArrayList<>();
    @Override void clear() { super.clear(); log.add("clear"); }  // ไม่มี constructor ไหนเรียก clear() อีกแล้ว
}

public class Main {
    public static void main(String[] args) {
        Cart c = new Cart();

        c.add(new Product("A", 10));
        c.add(new Product("B", 25));

        System.out.println(c.totalSatang());       // 35

S1 ออกแบบระบบที่จอดรถ Advance

โจทย์แบบนี้เจอทั้งในการสัมภาษณ์และข้อสอบที่ให้ร่างโครงสร้าง class ไม่ได้ตรวจว่าโค้ดครบทุกบรรทัด แต่ตรวจว่าเลือก class ถูก ซ่อนอะไรไว้ และรู้ว่าจุดไหนจะเปลี่ยน ข้อกำหนด มีที่จอดสองชนิด (มอเตอร์ไซค์ รถยนต์) รถเข้าแล้วได้ตั๋ว รถออกแล้วคิดเงินตามเวลาที่จอด อัตราต่างกันตามชนิดรถ และที่จอดเต็มต้องบอกผู้เรียกได้

แนวทางตอบ S1 พร้อมโค้ดที่รันแล้ว
การตัดสินใจเลือกอะไรเหตุผลและข้อแลกเปลี่ยน
รถกับตั๋วrecord Vehicle และ record Ticketเป็นข้อมูลที่ไม่เปลี่ยน ไม่ต้องมี setter ให้ใครแก้ผิดจุด
ชนิดรถenum VehicleTypeชุดชนิดปิดและเล็ก ถ้ามีพฤติกรรมต่างกันมากค่อยแยกเป็น class
การคิดเงินinterface PricingStrategyกฎราคาเปลี่ยนบ่อยและเปลี่ยนตามช่วงเวลาได้ สลับตัวเลือกโดยไม่แตะ ParkingLot ข้อเสียคือมีหน่วยเพิ่มอีกหนึ่งตัว
ที่จอดแต่ละช่องclass Spot ที่ซ่อนสถานะ takenมีแต่ occupy กับ release จึงไม่มีใครตั้งสถานะมั่ว ๆ
ที่จอดเต็มคืน Optional<Ticket>เต็มเป็นเรื่องปกติของโดเมน ไม่ใช่ข้อผิดพลาด ให้ผู้เรียกตัดสินใจเอง ส่วนตั๋วที่ใช้แล้วหรือไม่มีจริงเป็นข้อผิดพลาด จึง throw
เงินlong หน่วยบาทหรือสตางค์เลี่ยงปัญหาทศนิยม ในระบบจริงควรมีชนิด Money ของตัวเอง

คำถามที่ควรถามผู้ออกโจทย์ก่อน ได้แก่ เศษของชั่วโมงปัดอย่างไร (ในโค้ดปัดขึ้น ขั้นต่ำ 1 ชั่วโมง) มีหลายทางเข้าออกพร้อมกันไหม (ถ้ามี ต้องคิดเรื่อง thread-safety ซึ่งโค้ดนี้ยังไม่ได้ทำ) และหาช่องว่างแบบเรียงตามลำดับพอไหม หรือต้องใช้โครงสร้างที่เร็วกว่าเมื่อมีที่จอดหลายพันช่อง

import java.time.*;
import java.util.*;

enum VehicleType { MOTORCYCLE, CAR }

record Vehicle(String plate, VehicleType type) { }
record Ticket(String id, Vehicle vehicle, int spotId, Instant entry) { }

interface PricingStrategy { long fee(VehicleType type, Duration stay); }

class HourlyPricing implements PricingStrategy {
    private final Map<VehicleType, Long> ratePerHour;
    HourlyPricing(Map<VehicleType, Long> ratePerHour) { this.ratePerHour = Map.copyOf(ratePerHour); }

    public long fee(VehicleType type, Duration stay) {
        long hours = Math.max(1, (stay.toMinutes() + 59) / 60);     // ปัดขึ้นเป็นชั่วโมง ขั้นต่ำ 1 ชั่วโมง
        return hours * ratePerHour.get(type);
    }
}

class Spot {
    private final int id;
    private final VehicleType type;
    private boolean taken;

    Spot(int id, VehicleType type) { this.id = id; this.type = type; }
    int id() { return id; }
    boolean canTake(Vehicle v) { return !taken && v.type() == type; }
    void occupy() { taken = true; }
    void release() { taken = false; }
}

class ParkingLot {
    private final List<Spot> spots;
    private final PricingStrategy pricing;
    private final Map<String, Ticket> active = new HashMap<>();
    private int nextTicket = 1;

    ParkingLot(List<Spot> spots, PricingStrategy pricing) {
        this.spots = List.copyOf(spots);
        this.pricing = pricing;
    }

    Optional<Ticket> enter(Vehicle v, Instant now) {
        for (Spot s : spots) {
            if (s.canTake(v)) {
                s.occupy();
                Ticket t = new Ticket("T" + nextTicket++, v, s.id(), now);
                active.put(t.id(), t);
                return Optional.of(t);
            }
        }
        return Optional.empty();                                     // เต็ม ผู้เรียกตัดสินใจเอง
    }

    long exit(String ticketId, Instant now) {
        Ticket t = active.remove(ticketId);
        if (t == null) throw new IllegalArgumentException("unknown or already used ticket: " + ticketId);
        spots.stream().filter(s -> s.id() == t.spotId()).findFirst().orElseThrow().release();
        return pricing.fee(t.vehicle().type(), Duration.between(t.entry(), now));
    }
}

public class Main {
    public static void main(String[] args) {
        PricingStrategy pricing = new HourlyPricing(Map.of(VehicleType.CAR, 20L, VehicleType.MOTORCYCLE, 10L));
        ParkingLot lot = new ParkingLot(List.of(new Spot(1, VehicleType.CAR)), pricing);

        Instant t0 = Instant.parse("2026-01-01T09:00:00Z");
        Ticket t = lot.enter(new Vehicle("1กก-1234", VehicleType.CAR), t0).orElseThrow();
        System.out.println(t.id() + " spot " + t.spotId());                                  // T1 spot 1
        System.out.println(lot.enter(new Vehicle("2ขข-5678", VehicleType.CAR), t0).isPresent() ? "enter" : "full");   // full
        System.out.println("fee " + lot.exit(t.id(), t0.plus(Duration.ofMinutes(150))));    // fee 60
    }
}

Part C สถานการณ์ (ลองเขียนคำตอบเองก่อนเปิดดู)

C1. ระบบชำระเงินมี switch ตามชนิดการชำระ 6 case กระจายอยู่ 4 ที่ และทีมต้องเพิ่มวิธีใหม่ทุกไตรมาส จะ refactor อย่างไรโดยไม่ให้ของเดิมพัง

ข้อนี้ดูว่าเรารู้ลำดับที่ปลอดภัยหรือไม่ คำตอบที่ดีไม่ได้เริ่มจากการเขียน class ใหม่ แต่เริ่มจากทำให้มั่นใจว่าพฤติกรรมเดิมถูกล็อกไว้

  1. เขียน characterization test ครอบพฤติกรรมของแต่ละ case ในแต่ละที่ที่ switch อยู่ ตามผลที่โค้ดให้อยู่ตอนนี้ แม้บางผลดูแปลก ๆ ก็ล็อกไว้ก่อนแล้วจดไว้ว่าจะถามเจ้าของโดเมน
  2. สกัด interface เช่น PaymentMethod ที่มี method ที่ switch ทั้ง 4 ที่ต้องการ (เช่น fee(), validate(), settle()) ให้ละ method ต่อจุดใช้งาน ถ้ารวมไม่ได้ให้แยกเป็น interface เล็ก ๆ ตามบทบาท
  3. ทำทีละ switch ทีละ commit ให้ test ผ่านทุกก้าว ย้ายเนื้อใน case ไปเป็น implementation ของ interface แล้วให้ switch เดิมเรียกผ่าน interface
  4. เมื่อเหลือการ "แปลงชื่อหรือรหัสเป็น object" ที่เดียว ให้เก็บ switch นั้นไว้ในที่เดียว (factory หรือ registry) การเพิ่มวิธีชำระใหม่จึงเป็นการเพิ่ม class กับบรรทัด register ไม่ต้องไล่แก้ 4 ที่
  5. ลบ switch ที่ไม่จำเป็นออก และรัน test ทั้งชุดอีกครั้ง

ข้อแลกเปลี่ยนที่ควรพูดถึงคือ ถ้า case มีแค่สองสามตัวและไม่เพิ่ม ตัว switch ที่อ่านง่ายอาจดีกว่า การแตกเป็น class คุ้มเมื่อชนิดเพิ่มบ่อยและพฤติกรรมต่างกันจริง อีกทางเลือกที่ปลอดภัยกว่าสำหรับโดเมนปิดคือ sealed interface กับ switch แบบ pattern matching ที่คอมไพเลอร์ตรวจว่าครบทุกชนิด

C2. สายสืบทอด BaseReportService ลึก 5 ชั้น คนใหม่แก้ method หนึ่งแล้วรายงานอื่นพังซ้ำ ๆ ช่วยอธิบายเหตุผลให้เพื่อนร่วมทีมฟัง และเสนอแผนค่อย ๆ แก้

โจทย์นี้ดูทั้งความรู้และวิธีสื่อสาร ควรอธิบายสาเหตุก่อนเสนอทางแก้ และไม่ตำหนิคนเขียนเดิม เพราะสายสืบทอดแบบนี้มักค่อย ๆ โตขึ้นทีละนิด

สาเหตุที่อธิบายได้คือ fragile base class ลูกพึ่งรายละเอียดภายในของแม่ (ลำดับที่แม่เรียก method, field ที่แม่ใช้ซ้ำ) พอแม่เปลี่ยน ลูกที่ทับ method ไว้พังโดยที่ไม่มีใครแตะโค้ดลูก ยิ่งสูงยิ่งไล่ยาก ต้องเปิดห้าไฟล์เพื่อเข้าใจพฤติกรรมเดียว (yo-yo problem)

แผนที่ทำได้โดยไม่ต้องหยุดงานอื่น

  1. วาดแผนภาพว่า method ไหนอยู่ชั้นไหน และชั้นไหนถูกทับ ดูว่า "ความแตกต่างจริง" ของรายงานแต่ละตัวอยู่ที่ไหน มักเหลือไม่กี่เรื่อง เช่น แหล่งข้อมูล รูปแบบผลลัพธ์ กฎคัดกรอง
  2. เขียน test ครอบรายงานที่ใช้งานจริงมากที่สุดก่อน
  3. แยกแต่ละความแตกต่างเป็น interface เล็ก ๆ (DataSource, Formatter, Filter) แล้วให้ service รับผ่าน constructor เป็น composition
  4. ย้ายรายงานไปใช้โครงใหม่ทีละตัวใน PR เล็ก ๆ เมื่อสายเก่าไม่มีใครใช้แล้วค่อยลบ
  5. ถ้าเหลือขั้นตอนหลักที่เหมือนกันจริง ๆ ให้เก็บเป็น template method ชั้นเดียวที่เขียนเอกสารไว้ว่าอนุญาตให้ทับตรงไหนเท่านั้น และประกาศ method ที่ไม่ควรทับเป็น final

ข้อควรบอกคือ composition ไม่ได้ฟรี มีหน่วยเพิ่มและต้องประกอบให้ถูก ถ้าสายสืบทอดสั้น เสถียร และเป็น is-a จริง ก็ไม่ต้องแตะ

C3. class ReminderJob เรียก LocalDate.now() และ new SmtpClient() ในตัวเอง ต้องเขียน unit test ให้ จะทำอย่างไรโดยไม่เปลี่ยนพฤติกรรม

ปัญหาคือ class ซ่อน dependency สองตัว (เวลา และการส่งเมลจริง) ไว้ข้างใน เทสต์จึงให้ผลต่างกันตามวันที่รัน และอาจส่งเมลจริงออกไป ทางแก้คือสร้าง seam แล้วค่อยฉีดของปลอมเข้ามา

  1. เขียน characterization test คร่าว ๆ ก่อนถ้าทำได้ เพื่อบันทึกพฤติกรรมเดิม
  2. เพิ่ม constructor ที่รับ Clock และ interface MailSender (SmtpMailSender ห่อ SmtpClient เดิม) และเก็บ constructor เดิมไว้ให้เรียก this(Clock.systemDefaultZone(), new SmtpMailSender()) โค้ดเดิมที่เรียก new ReminderJob() จึงไม่ต้องแก้
  3. แทนที่ LocalDate.now() ด้วย LocalDate.now(clock) และ new SmtpClient() ด้วย field sender
  4. ในเทสต์ใช้ Clock.fixed(...) และ fake MailSender ที่เก็บข้อความไว้ใน list แล้วตรวจว่าส่งกี่ฉบับและถึงใคร

เหตุผลที่ใช้ fake ที่เก็บผลมากกว่า mock ที่ตรวจลำดับการเรียก คือเทสต์จะผูกกับ "ผลที่สังเกตได้" ไม่ใช่วิธีทำงานภายใน จึงไม่พังเมื่อ refactor ภายหลัง

ที่ชอบออกเป็นตัวลวงoverload เลือกตอนคอมไพล์ตามชนิดของตัวแปร override เลือกตอนรันตามชนิดของ object จริง field กับ static method ไม่มี dynamic dispatch (เป็น hiding) constructor ของแม่ทำงานก่อนลูก และอย่าเรียก method ที่ override ได้ใน constructor เปลี่ยน equals ต้องเปลี่ยน hashCode ด้วย และ equals(Product) ไม่ใช่การ override

Association vs Dependencyถือ reference เป็น field ระยะยาว / ใช้ชั่วคราวใน method (parameter, local)
Inheritance vs Compositionis-a ผูกตั้งแต่คอมไพล์ / has-a สลับตอนรันได้ ผูกหลวมกว่า
== vs equalsเทียบ reference / เทียบตามความหมายที่ class นิยาม (ต้องคู่กับ hashCode)
Pass-by-value vs by-referenceJava ส่งสำเนาของค่าเสมอ สำหรับ object ค่าคือ reference จึงแก้ state ได้แต่สลับตัวแปรของผู้เรียกไม่ได้
Encapsulation vs Abstractionซ่อนข้อมูลและรักษา invariant / เปิดเฉพาะสิ่งที่ผู้ใช้ต้องรู้ผ่านสัญญา
Strategy vs Template Methodสลับอัลกอริทึมตอนรันผ่าน composition / กำหนดโครงขั้นตอนไว้ในแม่ให้ลูกเติมบางขั้น
Decorator vs Proxyเพิ่มพฤติกรรมซ้อนกันได้ / คุมการเข้าถึง (สร้างทีหลัง ตรวจสิทธิ์ เรียกข้ามเครือข่าย)
Adapter vs Facadeแปลง interface หนึ่งให้เข้ากับที่ต้องการ / ซ่อนระบบย่อยหลายตัวไว้หลังหน้าตาง่าย
Factory Method vs Abstract Factorysubclass เลือกชนิด product หนึ่งอย่าง / factory สร้างชุดของ object ที่ต้องเข้ากัน
Stub vs Fake vs Mockคืนค่าตายตัว / ทำงานจริงแบบลัดทาง / ตรวจว่าถูกเรียกอย่างไร
SRP vs ISPclass หนึ่งมีเหตุผลให้เปลี่ยนเหตุผลเดียว / ผู้ใช้ไม่ควรถูกบังคับให้พึ่ง method ที่ไม่ใช้
LSP vs OCPลูกแทนแม่ได้โดยไม่ทำให้สัญญาเสีย / เพิ่มพฤติกรรมได้โดยไม่แก้ของเดิม
DIP vs DIหลักการ: พึ่ง abstraction / เทคนิค: ส่ง dependency เข้ามาจากข้างนอก
